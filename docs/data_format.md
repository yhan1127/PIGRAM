# Data Format

This document describes the data format used by PIGRAM.

PIGRAM uses two data levels:

1. **Raw structural samples**, stored under `data/raw/`.
2. **Processed patch--motif samples**, stored under `data/processed/` and used directly by training and evaluation.

The final training pipeline consumes:

```text
data/processed/train.pkl
data/processed/val.pkl
data/processed/test.pkl
```

Each file is a Python `List[Dict]`, where each dictionary represents one protein--nucleic-acid complex decomposed into protein patches and nucleic-acid motifs.

---

Raw data should be placed under:


## 2. Raw sample format

Each raw sample is a dictionary.

The required raw fields are:

```text
pdb
kind
protein_seq
protein_coords
partner_seq
partner_coords
contact_map
affinity
```

### `pdb`

Type:

```text
str
```

Structure or complex identifier.

### `kind`

Type:

```text
str
```

Observed values:

```text
prot-rna
prot-dna
```

### `protein_seq`

Type:

```text
str
```

Protein amino-acid sequence.

### `protein_coords`

Type:

```text
numpy.ndarray
```

Observed shape:

```text
[num_residues, 14, 3]
```

The raw RNA samples inspected contain protein coordinate arrays such as:

```text
[182, 14, 3]
[91, 14, 3]
[260, 14, 3]
[711, 14, 3]
```

The raw DNA samples inspected contain protein coordinate arrays such as:

```text
[326, 14, 3]
[323, 14, 3]
[327, 14, 3]
[313, 14, 3]
```

### `partner_seq`

Type:

```text
str
```

Nucleic-acid partner sequence.

### `partner_coords`

Type:

```text
numpy.ndarray
```

Observed shape:

```text
[num_nucleotides, 14, 3]
```

The raw RNA samples inspected contain partner coordinate arrays such as:

```text
[93, 14, 3]
[27, 14, 3]
[87, 14, 3]
[101, 14, 3]
```

The raw DNA samples inspected contain partner coordinate arrays such as:

```text
[25, 14, 3]
[12, 14, 3]
[26, 14, 3]
[7, 14, 3]
```

### `contact_map`

Type:

```text
numpy.ndarray
```

Observed shape:

```text
[num_residues, num_nucleotides]
```

Observed dtype in raw files:

```text
float64
```

### `affinity`

Type:

```text
NoneType or float
```

In the inspected structural training data, this field is present but often `None`.

## 5. Processed sample overview

Each processed sample is a dictionary representing one protein--nucleic-acid pair.

The processed sample contains:

```text
metadata fields
sequence fields
protein coordinate fields
protein patch fields
nucleic-acid motif fields

```

The most important model-facing fields are:

```text
protein_token_ids
patch_indices
patch_center_indices
patch_relative_distances
motif_type_ids
motif_lengths

motif_gc_content

motif_is_dna
patch_attr
motif_attr
patch_motif_label
patch_importance
patch_motif_structure_energy_v2
```

Some model-facing tensors are also constructed or normalized by:


## 13. Compatibility with older processed files

Some processed files may not explicitly store:

```text
motif_token_ids_list
motif_pairing_ratios
motif_gc_contents
```

In this case, the loader can infer or normalize missing model-facing fields from:

```text
protein_seq
partner_seq
secondary_structure
motifs
patch_indices
kind
na_source
```

This compatibility behavior is intended to support older processed pkl files while keeping the final model-facing tensor interface stable.

## 16. Distillation plan

The distillation plan is stored as:

```text
results/grammar/distill_plan.json
```

It contains:

```text
num_rules
min_rule_support
max_fine_clusters
min_fine_clusters
distill_plan
```

Each entry in `distill_plan` contains:

```text
rule_id
support
distill_on
num_fine_clusters
```

The default grammar setting uses:

```text
num_neg_rules = 3
num_pos_rules = 4
num_rules = 7
```

## 17. Downstream processed samples

Downstream processed candidate pools should follow the same processed sample schema as the main train/val/test files.

Expected downstream outputs:

```text
data/downstream_processed/manifest.json
data/downstream_processed/index.csv
data/downstream_processed/summary.csv
data/downstream_processed/*_downstream_val_processed.pkl
data/downstream_processed/*_downstream_test_processed.pkl
```

Additional downstream metadata may include:

```text
target
aptamer_id
affinity
label_high_topN
label_low_topN
```

Downstream evaluation preserves the original downstream candidate pools and does not perform pair-disjoint resplitting.
